# LoginBonus 1.0.0

全Paperサーバー共通のデイリークエストと連続ログイン報酬。Java 25 / Paper 26.2。本リポジトリは LoginBonus をビルドします。DailyQuests / LoginBonusは共通の報酬処理を含む独立プラグインで、別々のリポジトリとして公開しています。共通処理を修正する際は両リポジトリへ反映してください。

## 報酬

DailyQuestsは`quests.json`の215候補から日本時間の毎日0時に16件を選ぶ。採掘、林業・農業、戦闘、製作、生活の5分類。石100個で500 Dは毎日固定。毎日のボードはMySQLに確定保存し、再起動や途中の設定変更では変更しない。同一行動は条件が合う複数クエストを進める。

サバイバルとアドベンチャーの行動が対象。採掘分類は同一プレイヤー・サーバー・世界・座標を1日1回まで。導入後に観測した設置座標も採掘対象外とする。設置座標は保守的に保持するため、その後自然生成・再生成された同座標も対象外になり得る。林業・農業の再生産、Mobトラップは許可する。成熟作物だけを収穫として計上。過去のCoreProtect履歴・導入前の統計はクエストへ加算しない。クエストは任意で、全件クリアは必須ではない。

LoginBonusはMinecraftへの接続を日本時間の日付で記録する。全サーバー共通1日1回。接続中の日付変更はDetailedPlayerStatsの定期記録（通常30秒以内）でも検出する。Webログインは対象外。1日欠けると連続日数を1へリセットする。導入前のログインは報酬対象外。

初期設定の日額は `500 + 100*(連続日数-1) + 1000*floor(日数/7) + 5000*floor(日数/30) + 20000*floor(日数/100) + 100000*floor(日数/365)` DOLLARS。1日目500、2日目600、7日目2100、8日目2200、30日目12400。節目の加算は継続中の日額へ積み重なる。連続記録が伸びるほど日額が増えるため、長期運用時の発行量に応じて設定を調整する。

## 保存と入金

必須: DetailedPlayerStats **1.0.1以上**、MySQL、既存RelishEconomyの`balances`/`transactions`テーブル（InnoDB）。既定でWorldStateSyncのMySQL接続設定を継承。通貨は`relisheconomy` DBの`dollars`。Vaultの非トランザクション入金ではなく、既存カジノ・ポータル同様に既存残高へ直接入金する。

DetailedPlayerStatsのディスクジャーナルから、統計イベントと報酬キューを同一DBトランザクションで保存。報酬側は共有のワーカーロックで処理し、進捗・達成権利・キュー削除を同時に確定する。入金は残高行、報酬行の順でロックし、残高更新・RelishEconomy取引履歴・支給済み額を同じトランザクションで確定。複数サーバーや再送でも二重支給しない。ウォレット未生成時は入金待ちで再試行する。既存残高はDOUBLEのため、9兆Dを超える場合は精度保護のため入金を保留する。

遅れて届いたログイン日も日付順に連続日数を再計算する。修復で報酬が増えた場合は差額だけ入金する。各ログイン日には当時の報酬設定を保存する。正常時の反映は通常数秒〜数十秒。DB停止中のローカル記録はDetailedPlayerStatsの耐障害性に従う。過去記録・支給履歴は自動削除しない。

## コマンドと設定変更

- `/dailyquests`：本日のクエスト・進捗・報酬。
- `/loginbonus`：最終ログイン日・連続日数・報酬。
- 各コマンドの`status`：同じ情報（コンソールでは稼働状態）。
- `/dailyquests publish`：このサーバーの`plugins/DailyQuests/quests.json`と`config.yml`を全サーバーの今後のボードへ適用。
- `/loginbonus publish`：このサーバーの`plugins/LoginBonus/config.yml`を全サーバーの今後のログイン日へ適用。

publishには`rewards.admin`（既定OP）が必要。初回の共有設定登録は最初に起動したサーバーが行い、その後はpublishするまで共通設定を保持する。確定済みの当日ボードと過去ログイン日の設定は保持する。接続DB・通貨は全サーバーで同じものを使い、運用開始後に変更しない。

ポータル「クエスト・ボーナス」は本人の本日進捗、受け取り状態、現在・最長・累計ログイン、次回日額、最近60ログイン日の記録、最新100報酬履歴を表示する。報酬の受け取り操作は不要。

## ビルド・検証

JDK 25とMaven 3.9以降を使用し、リポジトリ直下で mvn clean verify を実行します。生成物: target/LoginBonus-1.0.0-26.2.jar。

ユニットテストは日本時間境界、報酬の単調増加、215候補の日替わり選択を検証。`DPS_TEST_DB/HOST/PORT/USER/PASSWORD`を隔離テストDBに指定すると、MySQLでクエストの対象外行動、同時処理、二重支給防止、入金失敗のロールバック、遅延ログインと差額支給、欠席時のリセットを検証する。テストDB内に模擬経済テーブルを作り、実プレイヤーの残高には触れない。
